Компилируемый язык **Nq**. Компилятор **nqc** на Go сам кодирует x86-64 и сам пишет
ELF64 / образ диска: никакого C, ассемблера и линкера.

## Сборка

    go build -o nqc .
    ./nqc run examples/hello.nq

## Режим — в начале файла, не флагом

| Директива | Что это | Запуск |
|---|---|---|
| `$hight` | обычная программа, безопасный код | всегда `./prog` |
| `$mid` | + небезопасное: `cast` ptr↔число, арифметика указателей | `./prog` (кроме ядра) |
| `$low` | + `asm("fa f4")` с сырыми байтами | `./prog` (кроме ядра/загрузчика) |
| `$mid`/`$low` + `$kernel` | ядро ОС, freestanding ELF64, вывод в VGA | нужен загрузчик |
| `$low` + `$boot` | загрузчик, образ диска (real mode → long mode) | QEMU/BIOS |

`$kernel` и `$boot` пишутся второй строкой или на той же: `$low boot`.
`$hight` + `$kernel`/`$boot` — ошибка: hight всегда живёт на ПК.
Главный файл обязан начинаться с директивы режима; импортируемые могут её не иметь
(тогда берут режим программы), а если имеют — режим должен совпасть.

## Синтаксис (не Go, но знакомый)

    fn имя(a: i64, p: ptr<u8>) -> i64 { ... }   // ": T" и "-> T" можно опускать, как в старом стиле
    let x = 5          // неизменяемая
    var y: u8 = 7      // изменяемая
    const N = 10 * 2   // константа времени компиляции
    if a { } else if b { } else { }
    while cond { }
    for let i = 0; i < n; i += 1 { }
    x += 1             // += -= *= /= %=
    deref(p) = 5       // или *p = 5;   addr(x) или &x
    cast(u8, x)  sizeof(i64)  sizeof(x)
    let a = make(i64, 10)   // массив: ptr<i64>, нулевая память (только обычные программы)
    a[i] = 5;  a[i] += 1;  a[i]   // индексация, работает и в $hight, границы не проверяются
    asm("fa f4")       // только $low

Точки с запятой не нужны. Тип возврата по умолчанию `i64` (без `return` вернёт 0).
`&&` и `||` с коротким вычислением. Приоритеты: `||` < `&&` < сравнения < `|` < `&` < `+ -` < `* / %`.

## Типы

`i64`, `i32`, `u64`, `u32`, `u16`, `u8`, `bool`, `void`, `ptr<T>` (голый `ptr` = `ptr<i64>`). Алиасы: `int`, `byte`.
- условия `if/while/for` только `bool`: пиши `x != 0`
- `u8` → `i64` неявно, обратно только `cast(u8, x)` или литерал 0..255
- `nil` подходит к любому `ptr`
- `addr(x)` — только у `var`; `deref(p)` читает/пишет по размеру `T` (1, 2, 4 или 8 байт)
- `p + n` сдвигает на `n * sizeof(T)`
- строка `"..."` имеет тип `ptr` (по адресу лежит длина, дальше байты)


## Версия 0.4

### Новые типы и операции

`i32`, `u16`, `u32`, `u64` в дополнение к `i64`, `u8`, `bool`. Загрузка и запись по указателю идёт по
размеру типа (1, 2, 4 или 8 байт). Целые расширяются неявно только «вверх» (`u8 → u16 → u32 → i64`);
вниз — `cast(u8, x)`. Константы проверяются по диапазону: `let b: u8 = 300` — ошибка компиляции.

Битовые операции `& | ^ ~ << >>` и `&= |= ^=`. Приоритеты: `||` < `&&` < сравнения < `|` < `^` < `&` < `<< >>` < `+ -` < `* / %`.
`>>` у беззнаковых логический, у знаковых арифметический; `u64` сравнивается, делится и сдвигается как беззнаковый.

### Глобальные переменные и статические массивы

    var ticks: i64 = 0          // с константным начальным значением
    let LIMIT: i64 = 100        // неизменяемая
    var table: [256]u64         // статический массив (bss, нули); значение table — ptr<u64>
    var idt: [256]IdtEntry      // массив структур

### Структуры как в C

Поля выравниваются по своему размеру, `sizeof` честный. `@packed` убирает выравнивание (для дескрипторов железа):

    @packed
    type IdtPtr struct { limit: u16, base: u64 }    // 10 байт

### Больше 6 параметров, указатели на функции

    fnaddr(handler)                     // адрес функции (u64)
    callfn(адрес, арг1, арг2, ...)      // вызов по адресу, до 6 аргументов

### Для ядер, драйверов и загрузчиков (`$kernel`, `$boot`)

Инструкции железа (только в этих режимах): `inb inw inl outb outw outl cli sti hlt pause rdtsc
readcr0/2/3/4 writecr0/3/4 rdmsr wrmsr lidt lgdt invlpg`.

Обработчики прерываний пишутся на Nq:

    @interrupt
    fn timer() { ticks += 1; pic_eoi(0) }       // регистры сохраняются, в конце iretq

    @exception
    fn page_fault(code: i64) { ... }            // код ошибки приходит параметром

Адрес в IDT: `idt_set(0x20, fnaddr(timer), 0x18, GATE_INT)`.

Библиотеки (на самом Nq, внутри `nqc`): `std.vga` (экран 80x25, прокрутка, цвета), `std.serial` (COM1),
`std.pic` (8259 + таймер PIT), `std.idt` (таблица прерываний), `std.pci` (шина PCI), `std.mem`
(`fill`, `copy`, `kalloc`). Пример мини-ОС: `examples/os/kernel.nq`, драйвер-заготовка: `examples/os/pci_scan.nq`.

### Загрузчик `$boot`

Сектор 512 байт читает программу с диска по LBA (до 900 секторов = 450 КБ), собирает карту памяти BIOS,
включает A20, отображает 1 ГиБ 1:1 (страницы по 2 МиБ), входит в long mode и передаёт управление `_start`.
Протокол для ядра: число записей E820 — `u32` по адресу `0x500`, сами записи по 24 байта с `0x504`;
селекторы GDT: `0x08` код32, `0x10` данные, `0x18` код64. Стек и bss `_start` ставит сам, за образом.
`nqc run kernel.nq` запускает образ в QEMU, если он установлен.

### Обычные программы: системные вызовы и аргументы

    syscall(номер, a1..a6)   // прямой вызов Linux x86-64, результат i64
    argc()   argv(i)         // аргументы командной строки (argv(i) — C-строка ptr<u8>)

`std.os`: `sys_open sys_read sys_write sys_close sys_lseek sys_unlink sys_mkdir getpid cbytes clen fd_puts print_cstr`.
Строки `"..."` теперь заканчиваются нулём, поэтому `cbytes("/tmp/x")` годится как путь для системных вызовов.
Пример: `examples/syscalls.nq`. На этой базе строятся сетевые и файловые библиотеки из `nq-libs`.

## Структуры

    type Node struct {
        value: i64,
        next: ptr<Node>,      // можно ссылаться на себя и на типы из импортов: ptr<пакет.Тип>
    }
    let n = make(Node, 1)     // ptr<Node>, нулевая память
    n.value = 5               // поля через точку, p[i].поле для массива структур
    sizeof(Node)              // 16 (поля выровнены как в C)

Структуры живут в памяти и используются только через `ptr<Имя>` (по значению в переменных,
параметрах и результатах — нельзя). Без `unsafe`, работает в `$hight`.

Пока нет: строки как отдельный тип, структуры по значению, дженерики.

## Импорты

    import "std.str"                    // встроенная библиотека (внутри nqc)
    import "lib/mathutil"               // файл проекта (examples/lib/mathutil.nq)
    import "sub/util"                   // файл в подпапке
    import "github.com/user/repo"       // установленный пакет
    import "std.math" as m              // свой псевдоним

Вызов: `slen(s)` или `str.slen(s)`. Если имя есть в двух импортах, `nqc` попросит
написать `пакет.имя(...)`. Встроенные: `std.str`, `std.math`, `std.mem`.

## nqc inst — установка библиотек

    nqc inst                        # просмотреть проект в текущей папке и скачать ВСЁ недостающее
    nqc inst myproject/             # то же для папки (или одного файла main.nq)
    nqc inst github.com/user/repo   # поставить/обновить одну библиотеку и её зависимости
    nqc inst github.com/user/repo@v1.2   # ветка или тег
    nqc list | nqc rm github.com/user/repo | nqc path

`nqc inst project` читает все `.nq` файлы проекта, находит `import "github.com/..."`,
скачивает то, чего нет (git clone, а без git — zip с GitHub), затем так же просматривает
файлы скачанных библиотек и докачивает их зависимости. В конце пишет, что не удалось найти.
Пакеты лежат в `~/.nq/pkg` (`$NQPKG`). Отдельной команды `nice` больше нет.

## Встроенные функции

`print(s)`, `puti(n)`, `exit(code)` — в `$kernel`/`$boot` пишут в VGA, иначе через syscall.
`alloc(n) -> ptr<u8>` и `make(T, n) -> ptr<T>` — память от системы (только обычные программы).

## Что изменилось по сравнению с nq1

- настоящие типы и проверки; `let` неизменяемая, `var` изменяемая
- `$mid`/`$low` стали настоящими уровнями; `$kernel`/`$boot`; рабочий загрузочный сектор
- пространства имён и `import ... as`; stdlib встроена в бинарник (раньше `std.str` не находился)
- `nqc inst project`: сам находит и скачивает все библиотеки проекта (git или zip с GitHub, ветки/теги)
- короткое вычисление `&&`/`||`, `else if`, `+=`, `->`, символы `'a'`, `asm("hex")`
- детерминированный порядок функций (раньше зависел от порядка обхода map)
- общий курсор VGA у `print` и `puti`
